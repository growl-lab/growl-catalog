CHECKSUM VERIFICATION
=====================

After downloading each .tar.gz archive, verified its integrity using PowerShell by comparing the 
local MD5 checksum against the checksum provided on Zenodo.

PowerShell commands:

"""
$archivePath = "path/to/downloaded/archive.tar.gz"
$expectedHash = "MD5 checksum copied from Zenodo"
$actualHash = (Get-FileHash -Algorithm MD5 -LiteralPath $archivePath).Hash

if ($actualHash -eq $expectedHash.Trim()) {
    Write-Host "MATCH: the archive matches Zenodo." -ForegroundColor Green
} else {
    Write-Host "MISMATCH: check the filename and copied checksum." -ForegroundColor Red
    Write-Host "Zenodo: $expectedHash"
    Write-Host "Local:  $actualHash"
}
"""

Repeated this procedure for each archive, replacing $archivePath
and $expectedHash with the corresponding filename and checksum.


DOWNLOAD ISSUE IN PART 1 AND WORKAROUND
=======================================
One Part 1 archive repeatedly failed to finish downloading in Chrome:

faccFIXEDbeta0.5fcore1.2zetaHG6.0RemMassFRYER2012SNDELAYED.tar.gz

Two browser attempts stopped near 2.9 GB after approximately two hours each. I switched to PowerShell and used this 
resumable download command from the directory where I wanted to save the archive:

"""
curl.exe -L -C - -o "faccFIXEDbeta0.5fcore1.2zetaHG6.0RemMassFRYER2012SNDELAYED.tar.gz" 
"https://zenodo.org/records/7080725/files/faccFIXEDbeta0.5fcore1.2zetaHG6.0RemMassFRYER2012SNDELAYED.tar.gz?download=1"
"""
I
 ran the same command four times in the same directory, retaining the partial file between attempts. The -C - option tells 
 curl to resume from the existing file size, if the server supports resuming. The PowerShell attempts took approximately 
 6–7 hours in total, in addition to the failed browser attempts.

Part 2 had no failed downloads and did not require resuming any archive.

OBSERVATIONS ABOUT DOWNLOAD SPEED
=================================
During Part 2, consecutive Chrome downloads sometimes seemed to slow down even though the internet connection appeared unchanged. 
Clearing the browser cache and refreshing the Zenodo page between downloads seemed to keep speeds more consistent; some files then 
finished in 20 minutes or less.

When refreshing did not help, I sometimes started a simultaneous curl.exe download in PowerShell. Chrome's download speed 
occasionally increased shortly afterward. Since curl itself was slower, I stopped the PowerShell download and continued in Chrome.

These are anecdotal observations, not verified fixes; the speed changes may have had other causes.
